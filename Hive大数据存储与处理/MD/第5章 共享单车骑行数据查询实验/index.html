    共享单车骑行数据查询实验¶

    本实验围绕某城市共享单车运营数据，完成 6 个查询任务，与课件《第 5 章 广电用户账单与订单数据查询进阶》的知识点一一对应，但业务场景与数据全部替换，可直接作为课堂实验或课后实训使用。

    实验任务 对应知识点
    任务 1 订单消费档次划分 条件函数、CAST 类型转换函数、DISTINCT、ORDER BY
    任务 2 统计用户每年骑行应付总额 字符函数（SUBSTR、CONCAT、LOWER 等）、分组聚合
    任务 3 统计用户每月骑行应付总额 日期获取类与日期计算类函数
    任务 4 统计用户月均骑行实付金额 数学函数（四则运算、ROUND、FLOOR、CEIL）
    任务 5 查询电助力订单的用户城市 内连接、外连接、左半开连接、UNION ALL
    任务 6 抽样统计用户骑行订单 桶表、TABLESAMPLE 抽样查询

    一. 实验目的¶

    • 掌握 Hive 内置函数的查看方法，能按需求选用条件、字符、日期、数学类函数。
    • 能使用 CASE 条件函数与 CAST 类型转换函数完成数据分档。
    • 能使用日期函数从时间字符串中取出年、月并完成按年、按月的分组统计。
    • 能使用数学函数计算实付金额与月均值。
    • 理解内连接、外连接与左半开连接的区别，能按业务场景选用正确的连接类型。
    • 能创建桶表并使用 TABLESAMPLE 完成抽样查询。

    二. 实验环境¶

    • Hadoop 3.x 集群（或伪分布式），Hive 3.x，HiveServer2 已启动。
    • 客户端：beeline -u jdbc:hive2://localhost:10000 -n zhangsan。
    • 数据文件存放于本地 /opt/data/ 目录（可自行调整，注意 LOAD DATA LOCAL 读的是客户端本地路径）。

    三. 实验数据准备¶

    1. 数据表及关系¶

    实验共 5 张表，均存放在数据库 sharedbike 中。

    表名 说明 主要字段
    bike_users 用户表 user_id、user_name、member_level、city、reg_time
    bike_info 单车信息表 bike_id、model、park_area、put_date
    bike_orders 骑行订单表（42 条） order_id、user_id、bike_id、prod_type、prod_name、order_time、cost
    bike_bills 骑行账单表（42 条） bill_id、user_id、fee_code、bill_time、should_pay、favour_fee
    bike_recharge 账户充值表（12 条） user_id、recharge_amt、recharge_time
    • bike_orders 记录用户下单购买的产品，订单金额 cost 为 STRING 类型（模拟原始数据），使用前需要转换。
    • bike_bills 记录每次骑行产生的费用明细，实付金额 = 应付金额 should_pay − 优惠金额 favour_fee。同一用户同一月份可有多条不同费用科目（fee_code）的明细。
    • 订单表与账单表通过 user_id 关联用户表，订单表通过 bike_id 关联单车表。
    • 数据刻意设计为：用户 U011 只充值、从未下单与骑行；用户 U012 有骑行账单但没有订单记录，供外连接与左半开连接实验对比。

    2. 建库与建表¶

    CREATE DATABASE IF NOT EXISTS sharedbike;
USE sharedbike;

    CREATE TABLE bike_users(
  user_id STRING,
  user_name STRING,
  member_level STRING,
  city STRING,
  reg_time STRING)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ',';

    CREATE TABLE bike_info(
  bike_id STRING,
  model STRING,
  park_area STRING,
  put_date STRING)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ',';

    CREATE TABLE bike_orders(
  order_id STRING,
  user_id STRING,
  bike_id STRING,
  prod_type STRING,
  prod_name STRING,
  order_time STRING,
  cost STRING)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ',';

    CREATE TABLE bike_bills(
  bill_id STRING,
  user_id STRING,
  fee_code STRING,
  bill_time STRING,
  should_pay DOUBLE,
  favour_fee DOUBLE)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ',';

    CREATE TABLE bike_recharge(
  user_id STRING,
  recharge_amt DOUBLE,
  recharge_time STRING)
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ',';

    四. 实验任务¶

    任务 1. 划分订单消费档次¶

    任务描述

    使用条件函数与类型转换函数，对骑行订单按订单金额划分消费档次。

    • 若订单金额大于等于 20.0，则消费档次认定为“高消费”；
    • 若订单金额大于等于 10.0 且小于 20.0，则认定为“中等消费”；
    • 若订单金额小于 10.0，则认定为“低消费”。
    • 消费档次列的列名为 consume_type，转换后的金额列名为 cost_f。
    • 查询结果按订单金额降序排列，并去除重复数据。

    实现思路

    • bike_orders 表中 cost 字段为 STRING 类型，需先用 CAST 显式转换为 FLOAT，才能参与数值比较与排序。
    • 用 CASE…WHEN…THEN 设置 3 个分支完成分档。
    • 用 DISTINCT 去除完全相同的重复行，用 ORDER BY 按转换后的金额降序排列。

    参考代码

    先用简单形式的 CASE 把产品类型编码翻译成中文。

    SELECT order_id, prod_type,
CASE prod_type
WHEN 'E' THEN '电助力单车'
WHEN 'B' THEN '经典单车'
WHEN 'M' THEN '月卡'
WHEN 'S' THEN '季卡'
ELSE '未知类型'
END AS `产品类型`
FROM bike_orders
LIMIT 5;

    再按金额划分消费档次。

    SELECT DISTINCT user_id, order_id, prod_name, CAST(cost AS FLOAT) AS cost_f,
CASE
WHEN cost >= 20.0 THEN '高消费'
WHEN cost >= 10.0 AND cost < 20.0 THEN '中等消费'
ELSE '低消费'
END AS consume_type
FROM bike_orders
ORDER BY cost_f DESC;

    预期结果

    第二条语句返回 42 行，前几行形如：

    user_id order_id prod_name cost_f consume_type
    U007 O0008 季卡-90天 79.0 高消费
    U007 O0025 季卡-90天 79.0 高消费
    U009 O0038 季卡-90天 79.0 高消费
    U001 O0041 月卡-30天 29.9 高消费
    U003 O0028 电助力单车-单次骑行 26.5 高消费
    … … … … …
    U001 O0026 经典单车-单次骑行 5.5 低消费

    中文列别名要用反单引号引起来；WHEN 后面的取值（20.0、10.0）是数值，与 cost 比较时 Hive 会先把 cost 隐式转换为 DOUBLE，所以即便不做 CAST 也能比较，但金额列的展示与排序仍需显式 CAST。

    任务 4. 统计用户月均骑行实付金额¶

    任务描述

    利用数学函数统计 2025 年月均骑行实付金额最高的 5 个用户。

    实现思路

    • 实付金额为应付金额减去优惠金额，即 should_pay - favour_fee。
    • 账单表记录的是每次骑行的费用明细，同一用户同一月份存在多条明细，因此月账单必须先用 SUM(should_pay - favour_fee) 把明细合并，再对月份求平均。直接对明细行取 AVG(should_pay - favour_fee)，得到的是单条明细的均值，不是月均账单。
    • 本任务按用户编号分组，月份数用 COUNT(DISTINCT MONTH(bill_time)) 单独统计，只计入有账单的月份。
    • 年份是行级过滤条件，写在 WHERE 中先过滤再聚合，不要写进 HAVING。
    • 用 ROUND(..., 2) 保留 2 位小数，按均值降序排序后取前 5 条。

    参考代码

    数学函数的用法。

    SELECT ROUND(3.14159, 2), FLOOR(3.7), CEIL(3.2);
SELECT FLOOR(-3.2), CEIL(-3.2);

    统计 2025 年月均骑行实付金额最高的 5 个用户。

    SELECT user_id,
       ROUND(SUM(should_pay - favour_fee) / COUNT(DISTINCT MONTH(bill_time)), 2) AS avg_fee
FROM bike_bills
WHERE YEAR(bill_time) = 2025
GROUP BY user_id
ORDER BY avg_fee DESC
LIMIT 5;

    预期结果

    user_id avg_fee
    U003 19.25
    U001 18.5
    U006 13.63
    U007 13.0
    U002 12.0
    • 结果恰好是 5 个用户，每人一行，因为只按 user_id 单列分组。
    • 去掉 LIMIT 5 后共 11 行，U011 因无账单不会出现。
    • 若去掉 WHERE YEAR(bill_time) = 2025，U001、U003 的 2024 年 12 月账单也会被计入分子与分母，结果随之改变——这正是年份过滤必须放在聚合之前的原因。
    • 若 favour_fee 存在空值，should_pay - favour_fee 的结果会变成 NULL 并被 SUM 忽略，此时需改写为 should_pay - COALESCE(favour_fee, 0)。

    拓展

    对月均值分别向下、向上取整。

    SELECT user_id,
       FLOOR(SUM(should_pay - favour_fee) / COUNT(DISTINCT MONTH(bill_time))) AS floor_fee,
       CEIL(SUM(should_pay - favour_fee) / COUNT(DISTINCT MONTH(bill_time))) AS ceil_fee
FROM bike_bills
WHERE YEAR(bill_time) = 2025
GROUP BY user_id;

    任务 5. 查询电助力订单的用户所在城市¶

    任务描述

    通过连接查询获取电助力单车订单的用户城市信息。

    实现思路

    • bike_orders 表用 prod_name 字段记录产品名称，电助力订单可用 LIKE '%电助力%' 模糊匹配筛选。
    • 订单表与用户表以 user_id 为连接条件内连接，从用户表取出订单表里没有的 city 字段。
    • 分别改用左外连接、左半开连接，观察结果集的变化。

    参考代码

    内连接：查询电助力订单的用户城市。

    SELECT o.order_id, o.prod_name, u.user_name, u.city
FROM bike_orders o
INNER JOIN
bike_users u
ON o.user_id = u.user_id
WHERE o.prod_name LIKE '%电助力%';

    内连接：查询产生订单的用户等级。

    SELECT u.user_id, u.user_name, u.member_level, o.order_id
FROM bike_users u
INNER JOIN
bike_orders o
ON u.user_id = o.user_id;

    左外连接：保留所有用户，从未下单的用户右表字段显示为 NULL。

    SELECT u.user_id, u.user_name, o.order_id, o.prod_name
FROM bike_users u
LEFT JOIN
bike_orders o
ON u.user_id = o.user_id;

    左半开连接：只取“有订单的用户”，结果中不能出现右表字段。

    SELECT u.user_id, u.user_name, u.city
FROM bike_users u
LEFT SEMI JOIN
bike_orders o
ON u.user_id = o.user_id;

    左半开连接错误示范：SELECT 中引用了右表字段。

    SELECT u.user_id, u.user_name, o.order_id
FROM bike_users u
LEFT SEMI JOIN
bike_orders o
ON u.user_id = o.user_id;

    用 UNION ALL 纵向合并订单记录与充值记录。

    SELECT user_id, 'order' AS rec_type, CAST(cost AS STRING) AS amount
FROM bike_orders
UNION ALL
SELECT user_id, 'recharge' AS rec_type, CAST(recharge_amt AS STRING) AS amount
FROM bike_recharge;

    预期结果

    • 电助力订单共 11 条，涉及 U001、U003、U006、U007 四位用户，结果形如 O0001 | 电助力单车-单次骑行 | 张伟 | 杭州。
    • 订单与用户的内连接返回 42 行。
    • 用户表左外连接订单表返回 44 行：U011、U012 各多出一行，其 order_id、prod_name 为 NULL。
    • 左半开连接返回 10 行（U001—U010），U011、U012 被排除；把右表字段写进 SELECT 会直接报错。
    • UNION ALL 返回 54 行（42 + 12），其中 U011 只有充值记录。

    UNION ALL 要求各子查询的列数、列名与列类型一致，因此 DOUBLE 类型的 recharge_amt 需要用 CAST 转成与 cost 相同的 STRING 类型。若要去重则改用 UNION。

    任务 6. 抽样统计用户骑行订单¶

    任务描述

    利用抽样查询对用户骑行订单进行抽样统计。

    实现思路

    • 创建桶表 bike_orders_bucket，按用户编号 user_id 分为 4 个桶。
    • 从 bike_orders 向桶表中导入数据。
    • 使用 TABLESAMPLE(BUCKET x OUT OF y ON user_id) 抽取指定桶的数据并统计条数。

    参考代码

    创建桶表。

    CREATE TABLE bike_orders_bucket(
  user_id STRING,
  order_id STRING,
  prod_name STRING,
  order_time STRING,
  cost STRING)
CLUSTERED BY(user_id) INTO 4 BUCKETS
ROW FORMAT DELIMITED
FIELDS TERMINATED BY ',';

    向桶表导入数据。

    INSERT OVERWRITE TABLE bike_orders_bucket
SELECT user_id, order_id, prod_name, order_time, cost
FROM bike_orders;

    抽取第 3 个桶的数据。

    SELECT * FROM bike_orders_bucket
TABLESAMPLE(BUCKET 3 OUT OF 4 ON user_id);

    统计每个桶中的数据条数。

    SELECT COUNT(*) FROM bike_orders_bucket
TABLESAMPLE(BUCKET 1 OUT OF 4 ON user_id);

    预期结果

    • 桶表共 42 条数据，4 个桶的条数由 user_id 的哈希值决定，不一定完全均分。
    • TABLESAMPLE(BUCKET 1 OUT OF 4 ON user_id) 返回其中 1 个桶的数据，x 换成 2、3、4 即抽取对应桶。
    • 由于只扫描单个桶，抽样查询避免了全表遍历，可用于快速估算与数据探查。

    现象 原因与处理
    LOAD DATA LOCAL 报文件不存在 LOCAL 读的是 beeline 客户端本地路径，不是 HDFS 路径；若文件已在 HDFS 上，去掉 LOCAL
    CASE 报类型不匹配 WHEN 后的取值类型必须与判断字段完全一致，例如 prod_type 是 STRING，就要写成 WHEN 'E'
    中文列别名报错 中文别名必须用反单引号 ` 引起来
    左半开连接报 SemanticException 左半开连接的 SELECT 与 WHERE 中都不能引用右表字段
    UNION ALL 报列数或类型不一致 保证各子查询列数相同、列名以第一条 SELECT 为准、对应列类型一致，必要时用 CAST 统一
    抽样查询报桶数不匹配 TABLESAMPLE(BUCKET x OUT OF y ON field) 中的 y 必须是桶数的倍数或因子
    金额计算结果为空 参与运算的字段若存在 NULL，需先用 COALESCE(字段, 0) 兜底
