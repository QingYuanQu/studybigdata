# 实验：员工工资对象序列化

> 配套教程：4-3-1 ~ 4-3-6，以及「部门工资总额」实训。
> 上次做部门工资总额时，map 输出的 value 是一个 `IntWritable(工资)`——一行数据里我们只用到了一个字段。
> 这次把整行员工记录都装进对象里传，顺其自然地体会**自定义 Writable 存在的理由**。

## 一、实验目的

1. 把上一轮的部门工资实验升级为对象序列化版本，理解从 `IntWritable` 到自定义 `Writable` 的动机；
2. 实现 `EmployeeWritable`，处理「字段可能为空」的真实数据（`comm` 奖金字段经常为空）；
3. 在 Reducer 中同时使用对象里的多个字段（工资、奖金），完成单个 `IntWritable` 做不到的统计。

## 二、实验环境

- JDK 8、Maven 工程（依赖 hadoop-client 3.1.3）
- Windows 本地模式即可运行（`winutils.exe` 已配置）

## 四、实验一：EmployeeWritable 本地序列化

### 4.1 定义 EmployeeWritable

这次不选全部 8 个字段——**Writable 只序列化业务需要的字段**（对比 4-3-3 篇 `Serializable` 连字段带元数据全搬的做法）。我们选 5 个：

`empno`（int）、`ename`（String）、`sal`（int）、`comm`（int）、`deptno`（int）。

在 `entity` 包里新建（对照 4-3-6 篇 ComputerWritable 的六步）：

```java
package com.studybigdata.hadoop.java.entity;

import org.apache.hadoop.io.Writable;

import java.io.DataInput;
import java.io.DataOutput;
import java.io.IOException;

/**
 * 一条员工工资记录（emp 表的业务子集）。
 * sal 是工资，comm 是奖金；comm 可能为空，反序列化前由 Mapper 兜底成 0。
 */
public class EmployeeWritable implements Writable {

    private int empno;
    private String ename;
    private int sal;
    private int comm;
    private int deptno;

    public EmployeeWritable() {
    }

    public EmployeeWritable(int empno, String ename, int sal, int comm, int deptno) {
        this.empno = empno;
        this.ename = ename;
        this.sal = sal;
        this.comm = comm;
        this.deptno = deptno;
    }

    public int getEmpno() { return empno; }
    public void setEmpno(int empno) { this.empno = empno; }
    public String getEname() { return ename; }
    public void setEname(String ename) { this.ename = ename; }
    public int getSal() { return sal; }
    public void setSal(int sal) { this.sal = sal; }
    public int getComm() { return comm; }
    public void setComm(int comm) { this.comm = comm; }
    public int getDeptno() { return deptno; }
    public void setDeptno(int deptno) { this.deptno = deptno; }

    // 序列化：顺序为约定，写好不可单方面改
    @Override
    public void write(DataOutput out) throws IOException {
        out.writeInt(empno);
        out.writeUTF(ename);
        out.writeInt(sal);
        out.writeInt(comm);
        out.writeInt(deptno);
    }

    // 反序列化：读取顺序必须和 write 完全一致
    @Override
    public void readFields(DataInput in) throws IOException {
        this.empno = in.readInt();
        this.ename = in.readUTF();
        this.sal = in.readInt();
        this.comm = in.readInt();
        this.deptno = in.readInt();
    }

    @Override
    public String toString() {
        return "EmployeeWritable{empno=" + empno + ", ename='" + ename + "', sal=" + sal
                + ", comm=" + comm + ", deptno=" + deptno + "}";
    }
}
```

### 4.2 写出去、读回来

仿照 4-3-6 篇，用 emp 表第一行 SMITH 验证：

```java
// EmployeeOut：写出
EmployeeWritable e1 = new EmployeeWritable(7369, "SMITH", 800, 0, 20);
DataOutputStream dos = new DataOutputStream(new FileOutputStream("employee.bin"));
e1.write(dos);
dos.close();

// EmployeeIn：读回
EmployeeWritable e2 = new EmployeeWritable();   // 先有对象，再填值
DataInputStream dis = new DataInputStream(new FileInputStream("employee.bin"));
e2.readFields(dis);
dis.close();
System.out.println(e2);
```

预期输出：

```
EmployeeWritable{empno=7369, ename='SMITH', sal=800, comm=0, deptno=20}
```

想一想：`comm` 我们传的是 `0`，不是「空」。**Writable 的字段类型是定死的，没有「空」这个状态**——缺失数据必须在进 Mapper 时兜底，这是和数据库 NULL 最大的区别。

## 五、实验二：MapReduce——按部门统计工资与奖金

### 5.1 业务背景：为什么 value 要换成对象

上一轮部门工资实验里，Reduce 只需要 `sal` 一个字段，`IntWritable` 够用。
现在需求升级为：**按部门统计 人数、工资合计、奖金合计**。

一条记录要同时带 `sal` 和 `comm` 两个字段过去，`IntWritable` 装不下了——这正是自定义 Writable 的用武之地：**map 输出的 value 从「一个数」变成「一条结构化记录」**。

### 5.2 Mapper

```java
package com.studybigdata.hadoop.mapred.cserializable;

import com.studybigdata.hadoop.java.entity.EmployeeWritable;
import org.apache.hadoop.io.LongWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Mapper;

import java.io.IOException;

/**
 * 每行 emp 记录解析成 EmployeeWritable，key 用部门编号，按部门分组。
 */
public class EmployeeMapper extends Mapper<LongWritable, Text, IntWritable, EmployeeWritable> {

    private final IntWritable outKey = new IntWritable();
    private final EmployeeWritable outValue = new EmployeeWritable();

    @Override
    protected void map(LongWritable key, Text value, Context context)
            throws IOException, InterruptedException {
        String line = value.toString().trim();
        if (line.isEmpty()) {
            return;
        }
        String[] f = line.split(",");
        // 第 1 行是表头：empno 不是数字，直接跳过
        if (!f[0].trim().matches("\\d+")) {
            return;
        }

        // comm 可能为空串：parseInt 会抛 NumberFormatException，必须兜底成 0
        int comm = f[6].trim().isEmpty() ? 0 : Integer.parseInt(f[6].trim());

        outValue.setEmpno(Integer.parseInt(f[0].trim()));
        outValue.setEname(f[1].trim());
        outValue.setSal(Integer.parseInt(f[5].trim()));
        outValue.setComm(comm);
        outValue.setDeptno(Integer.parseInt(f[7].trim()));

        outKey.set(outValue.getDeptno());
        context.write(outKey, outValue);
    }
}
```

三个容易踩的坑，注释里都点了：

1. **表头行**：`empno` 解析不出数字，用正则挡掉；
2. **comm 为空**：`Integer.parseInt("")` 直接异常，空串兜底成 0（相当于 SQL 里的 `COALESCE(comm, 0)`）；
3. **对象复用**：`outValue` 在成员位置只 new 一次，每行重新 `set`——和 4-3-5 篇讲的一致。

### 5.3 Reducer

```java
package com.studybigdata.hadoop.mapred.cserializable;

import com.studybigdata.hadoop.java.entity.EmployeeWritable;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Reducer;

import java.io.IOException;

/**
 * 按部门统计：人数、工资合计、奖金合计。
 * value 必须是 EmployeeWritable 才能同时拿到 sal 和 comm。
 */
public class EmployeeReducer extends Reducer<IntWritable, EmployeeWritable, IntWritable, Text> {

    @Override
    protected void reduce(IntWritable dept, Iterable<EmployeeWritable> values, Context context)
            throws IOException, InterruptedException {
        int count = 0;
        int totalSal = 0;
        int totalComm = 0;

        for (EmployeeWritable e : values) {
            count++;
            // 当场取值（4-3-5 篇 5.9 节：values 里是同一个实例反复填值）
            totalSal += e.getSal();
            totalComm += e.getComm();
        }

        context.write(dept, new Text(count + " 人, 工资合计=" + totalSal + ", 奖金合计=" + totalComm));
    }
}
```

### 5.4 Driver

与 ComputerJob 唯一的区别是 map 输出 key 变成了部门编号：

```java
job.setMapOutputKeyClass(IntWritable.class);
job.setMapOutputValueClass(EmployeeWritable.class);   // 本实验的关键一行
job.setOutputKeyClass(IntWritable.class);
job.setOutputValueClass(Text.class);
```

完整类（放 `cserializable` 包，输入 `data/mapred/emps.txt`）：

```java
package com.studybigdata.hadoop.mapred.cserializable;

import com.studybigdata.hadoop.java.entity.EmployeeWritable;
import org.apache.hadoop.conf.Configuration;
import org.apache.hadoop.fs.Path;
import org.apache.hadoop.io.IntWritable;
import org.apache.hadoop.io.Text;
import org.apache.hadoop.mapreduce.Job;
import org.apache.hadoop.mapreduce.lib.input.FileInputFormat;
import org.apache.hadoop.mapreduce.lib.output.FileOutputFormat;

public class EmployeeJob {

    public static void main(String[] args) throws Exception {
        String input = args.length > 0 ? args[0] : "data/mapred/emps.txt";
        String output = args.length > 1 ? args[1] : "data/mapred/output-employee";

        Configuration conf = new Configuration();
        Job job = Job.getInstance(conf, "employee-salary");
        job.setJarByClass(EmployeeJob.class);

        job.setMapperClass(EmployeeMapper.class);
        job.setReducerClass(EmployeeReducer.class);

        job.setMapOutputKeyClass(IntWritable.class);
        job.setMapOutputValueClass(EmployeeWritable.class);

        job.setOutputKeyClass(IntWritable.class);
        job.setOutputValueClass(Text.class);

        FileInputFormat.addInputPath(job, new Path(input));
        FileOutputFormat.setOutputPath(job, new Path(output));

        System.exit(job.waitForCompletion(true) ? 0 : 1);
    }
}
```
